# 2026-01-26 xas99 alignment

## Goal

Align the Tawny assembler output with xas99 for `sd/typewriter.asm`.

## Setup

- Created a local xas99 skill (`skills/xas99-assembler/SKILL.md`) with a standard procedure for generating listings and comparing them against Tawny output.
- Built the xas99 listing with `-R` to accept `R0`/`R1` register syntax.
- Built the Tawny listing with `dotnet run --project tawny -- asm ...`.

## Comparison procedure (high level)

1. Generate xas99 listing:
   - `~/.local/bin/xas99 -R -L scratch/typewriter.xas99.lst -o scratch/ sd/typewriter.asm`
2. Generate Tawny listing:
   - `dotnet run --project tawny -- asm sd/typewriter.asm -o scratch`
3. Compare emitted words by address, ignoring comments and listing formatting.

## Findings

Initial comparisons showed a block of mismatches starting at `0080` and an extra word at `00A6`. The diffs pointed to single-operand opcode base values and `LIMI` encoding.

## Fixes

- Updated single-operand opcode bases in `tawny/Assembler/Assembler.cs` to match xas99:
  - `BLWP` 0x0400, `CLR` 0x04C0, `NEG` 0x0500, `INV` 0x0540, `INC` 0x0580, `INCT` 0x05C0,
    `DEC` 0x0600, `DECT` 0x0640, `SWPB` 0x06C0, `SETO` 0x0700, `ABS` 0x0740.
- Treated `LIMI` as a two-word immediate instruction in `tawny/Assembler/Assembler.cs` (opcode `0x0300` + immediate word).
- Updated disassembly in `tawny/Program.cs` to match the new `LIMI` size and single-operand opcode bases.
- Ensured the assembler recognizes `LIMI` during both passes.

## Result

After rebuilding, the Tawny listing matched the xas99 listing for `sd/typewriter.asm` with no remaining word-level diffs.
